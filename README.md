# Data Science Bootcamp

## Тестовое задание: кандидатогенерация для категории услуг

### О задаче

Пользователи Авито ищут услуги короткими запросами:

- «автоподбор»,
- «скупка телевизоров»,
- «баня на дровах»,
- «монтаж видеодомофонов»,
- «обзвон по базе».

По каждому такому запросу в корпусе находятся тысячи объявлений исполнителей. Поиск устроен каскадом: сначала этап кандидатогенерации быстро отбирает из всего корпуса небольшое множество подходящих объявлений, а затем модели ранжирования упорядочивают только их.

Главное требование к кандидатогенерации — полнота. Если нужное объявление не попало в кандидаты, никакое ранжирование его уже не вернёт.

В этой задаче нужно решить этап кандидатогенерации: по поисковому запросу найти объявления, которые стоит передать дальше, на ранжирование.

### Цель задания

Разработать решение, которое для каждого поискового запроса отбирает из корпуса до 50 объявлений — кандидатов, которые дальше уйдут на ранжирование.

Решение:

- Получает на вход поисковый запрос: его текст и остальные признаки.
- Находит в корпусе объявлений услуг те, что подходят под этот запрос.
- Возвращает до 50 item_id найденных объявлений.

Подходящие объявления — те, которые пользователь в итоге выбрал по этому запросу. Обычно это одно-два объявления, иногда больше. Решение должно поймать их в свои 50 кандидатов: качество — это доля подходящих объявлений, которые туда попали.

### Ожидаемый результат

Ответ нужно подготовить в файле `answer.csv` — CSV с разделителем «запятая», в кодировке UTF-8, ровно с двумя колонками:

| Колонка | Тип | Описание |
| --- | --- | --- |
| `query_id` | строка | идентификатор запроса из `benchmark_queries.parquet`, ровно 16 символов (регистр важен) |
| `answer` | строка | до 50 `item_id` через пробел |

`item_id` — строка ровно из 16 символов `0-9a-f` (например, `1382564bf8994a83`), ровно в том виде, в каком она лежит в `benchmark_items.parquet`.

Требования к файлу:

- строка на каждый `query_id` из `benchmark_queries.parquet`: без пропусков, лишних строк и повторов; порядок строк любой;
- не больше 50 `item_id` в одной строке, без повторов внутри строки;
- все `item_id` должны существовать в `benchmark_items.parquet`;
- нужно возвращать именно идентификаторы объявлений (`item_id`), а не заголовки или номера строк;
- других колонок, в том числе колонки с индексом, быть не должно.

Пример `answer.csv`:

```
query_id,answer
00WuFMaXSFZBxSzT,1382564bf8994a83 121fa7f5e765ce00 f3801ec4fa472597 ...
03ztb1gtRFC4K4vP,b0dd913d84ca1f61 e36f6c3245e05ab6 a3c3aa4703977bfe ...
```

#### Сохранение предсказаний в Python

Здесь `query_ids` — идентификаторы запросов из `benchmark_queries.parquet`, `predictions` — для каждого запроса список до 50 `item_id`.

```python
answer = pd.DataFrame({
    'query_id': query_ids,                                   # строки
    'answer': [' '.join(top50) for top50 in predictions],     # строки
})
answer.to_csv('answer.csv', index=False)
```

### Целевая метрика

Решение будет оцениваться по метрике Recall@50.

Для одного запроса считается доля подходящих объявлений, которые попали в твой топ-50. Затем значение усредняется по всем запросам:

```
Recall@50 = mean_по_запросам( |топ-50 ∩ релевантные| / |релевантные| )
```

Пример на трёх запросах:

| Запрос | Подходящих объявлений | Из них в твоих 50 | Вклад запроса |
| --- | --- | --- | --- |
| А | 1 | 1 | 1/1 = 1.0 |
| Б | 2 | 1 | 1/2 = 0.5 |
| В | 1 | 0 | 0/1 = 0 |

```
Recall@50 = (1.0 + 0.5 + 0) / 3 = 0.5.
```

Порядок объявлений в ответе на метрику не влияет.

У тебя будет 7 попыток. Засчитывается наилучший результат.

Отдельно проверь сами item_id: если они записаны не так, как в корпусе (другой регистр, лишние символы, слитная строка), ошибки не будет — такие объявления просто не засчитаются и займут место в ответе, а метрика молча просядет.

Частые ошибки:

- query_id и item_id приведены к числу и потеряли ведущие нули или перешли в экспоненциальную запись — это строки, работай с ними как со строками и не открывай answer.csv в Excel;
- файл сохранён с индексом — используйте to_csv(index=False);
- item_id записаны через запятую или списком ['a', 'b'] — нужен один пробел между ними;
- item_id приведены к верхнему регистру — нужны строчные буквы, как в корпусе.
